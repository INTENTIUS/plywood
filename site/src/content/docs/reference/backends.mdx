---
title: 'Backends'
description: 'The backend URLs plywood reads, and the features each gives the pipeline.'
---

| Backend | URL | The pipeline gets |
|---|---|---|
| Pulumi Cloud | `https://api.pulumi.com` | state, history, ESC, Insights and RBAC in Pulumi Cloud; Pulumi Cloud's stack lock orders updates |
| File | `file://~/.pulumi` | for local runs |
| S3 | `s3://bucket` | state in your bucket, with OIDC roles; `plywood init` checks the bucket |
| GCS | `gs://bucket` | the same, on Google Cloud |
| Azure Blob | `azblob://container` | the same, on Azure |
| plunge | `plunge+file://`, `plunge+s3://`, `plunge+gs://` and `plunge+azblob://` | one record per resource and markers on each object |

plywood reads a stack's backend from `backend` in `plywood.yml` (for every stack or per stack), then `PULUMI_BACKEND_URL`, then `backend.url` in `Pulumi.yaml`. A `plunge+` URL picks the plunge engine.
