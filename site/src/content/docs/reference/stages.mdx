import { Tabs, TabItem } from '@astrojs/starlight/components';

| Stage | Runs on | Writes |
|---|---|---|
| `check` | every push | the check report |
| `preview` | every pull request push and `/plywood preview` | the note, the status, the change set |
| `up` | merge, or `/plywood up` | the update, its ledger row and the snapshot |
| `drift` | the schedule | one issue per drifted stack |

<Tabs syncKey="engine">
<TabItem label="Pulumi">
| Stage | Command |
|---|---|
| `check` | `plywood.yml`'s checks, then the repository's check hooks (such as `pre-commit`) read at the base commit |
| `preview` | `pulumi preview --json`, one run giving the change set and CrossGuard's verdict |
| `up` | `pulumi preview --json` again, compared with the approved shape, then `pulumi up --yes --json`, then `pulumi stack export` for the snapshot |
| `drift` | `pulumi refresh --preview-only --json --target <urn>`, one resource at a time |
</TabItem>
<TabItem label="plunge">
| Stage | Command |
|---|---|
| `check` | the same as Pulumi |
| `preview` | `plunge preview --json --save-plan <file>`, the plan file in a scratch directory outside the working tree |
| `up` | `plunge up --plan <file> --yes --json`, which refuses a record that moved |
| `drift` | `plunge drift --resource <urn> --stream` |

With plunge, the pipeline also gets a saved plan stamped with each record's version. plunge's [claims page](https://intentius.io/plunge/claims/) records the runs behind it.
</TabItem>
</Tabs>
