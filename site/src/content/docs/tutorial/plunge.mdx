Install [plunge](https://intentius.io/plunge/) v0.1.0, then adopt the `dev` stack:

```sh
pulumi stack export --stack dev --file dev.json
plunge stack adopt --file dev.json --stack dev --json
```

Point the stack at a `plunge+` backend in `plywood.yml`:

```yaml
stacks:
  shop/dev:
    backend: plunge+s3://plywood-tutorial-state?endpoint=localhost:4566
```

## Two pull requests, one stack

Open one pull request that changes the `events` queue and another that changes `worker-0`. plywood locks per resource, so each pull request holds only the URNs its preview touches. Approve and merge both.

<WithPlunge feature="two updates to different resources of one stack that run side by side, with no stack lock" />

Each `up` applies a saved plan. The plan carries the version of each record it read, so a record another update moved makes `plunge up` refuse with exit 40. plywood reports that as chant's moved-plan code, the same code a stock stack gets for a moved preview.
